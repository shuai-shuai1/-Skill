# GPT Image 2 到 PowerPoint 可编辑高保真复现

## 目录

- 启用条件与产物契约
- GPT Image 2 参考图
- 参考图拆层与 PowerPoint 重建
- 渲染、像素比较与对齐
- 验收层级与最终交付

这是 `figure` 模式的可选分支。目标是先获得合格科研视觉参考，再用 PowerPoint 重建为可编辑图件，通过参考图与 PPT 渲染图的像素差异不断收敛。

“像素级”是 QA 方法，不是对任意外部作品逐像素复制的授权。

## 启用条件

同时满足以下条件时启用：

- 用户明确要求 GPT Image 2、PPT 可编辑复现或高保真像素对比；
- 图件包含适合生成式位图的概念、材质或复杂示意元素；
- 来源是用户自有、AI 新生成、已授权、公有领域或许可证允许高保真复现；
- 最终需要 `.pptx` 和可编辑分层对象。

若图主要由真实数据、公式、坐标轴、电路或严格拓扑组成，先用代码或专业矢量工具生成准确核心；GPT Image 2 只能提供非关键视觉素材。

## 产物契约

从 `assets/templates/ppt_reproduction_spec.md` 创建任务书，至少记录：

- 来源与版权状态；
- 参考图、最终画幅和目标尺寸；
- 锁定结构、文字、颜色、字体与允许偏差；
- GPT Image 2 提示词和生成路径；
- PPT 图层清单与对象职责；
- 渲染工具和比较阈值；
- 已知偏差和人工验收结论。

## 阶段一：生成或准备参考图

1. 使用环境中的 `imagegen` Skill，不自建 OpenAI SDK 调用器。
2. 默认走内置图像生成工具；只有用户明确选择 CLI/API 路径时才使用对应 fallback。
3. 把项目要消费的最终参考图复制到工作区，不能只留在默认生成目录。
4. 使用 `scientific-educational` 用例，指定白底、低饱和、清晰分区、少遮挡和无水印。
5. 避免把长文本、精确数字、坐标轴、公式和连接关系烘焙进位图。
6. 如需透明素材，按 `imagegen` Skill 的透明图流程处理并验证 alpha。
7. 保存最终提示词、输入图角色、模型路径说明和生成版本。

若环境无法明确选择模型，不要声称使用了特定模型。用户明确要求 `gpt-image-2` 时，使用环境支持的显式 GPT Image 2 路径或说明当前工具不暴露模型选择。

## 阶段二：参考图拆层

把参考图分为：

- 背景与非关键纹理；
- 主面板与分区边界；
- 科研对象或设备素材；
- 模块、节点和连接；
- 标题、标签、变量和图例；
- 数据图、坐标轴和公式；
- 装饰与阴影。

决定每层的实现方式：

- 文字、线、箭头、边界框和简单模块：PowerPoint 原生可编辑对象；
- 复杂关系网络：Graphviz 后导入；
- 数据图：代码生成 SVG/PDF/PNG 后放入 PPT；
- GPT Image 2 生成的复杂位图：作为裁切后素材或背景层；
- 不稳定的 AI 文字：删除并用 PPT 文本重建。

## 阶段三：PowerPoint 重建

执行时调用环境中的 Presentations Skill，并遵守其当前实现约束。当前推荐路径是使用 `@oai/artifact-tool` 的 JavaScript ES module 生成或编辑 PPT，不使用 `python-pptx`。

1. 选择与参考图一致的画布比例和尺寸。
2. 先建立坐标系统、边距、基准线和面板框架。
3. 创建连接线后创建节点，避免线穿过模块和文字。
4. 依次实现大结构、主要对象、标签、细节和装饰。
5. 所有正文文字使用 PPT 文本对象，保持可编辑。
6. 数据图保持独立文件和来源，不从 AI 图中描数。
7. 为每个对象使用稳定 ID 或对象清单，便于下一轮局部调整。
8. 不覆盖用户给出的源 PPT；在副本或独立输出中工作。

## 阶段四：渲染与像素比较

1. 用 Presentations Skill 的渲染工具把目标幻灯片导出为 PNG。
2. 确保参考图与候选图具有相同宽高、色彩模式和背景。
3. 运行：

```text
python scripts/compare_figure_renders.py reference.png candidate.png \
  --output qa/compare.json --diff qa/diff.png --overlay qa/overlay.png
```

4. 查看至少四项指标：归一化 MAE、RMSE、超过阈值的像素占比、边缘 MAE。
5. 同时检查全尺寸图和差分图。指标不能发现文字语义、连接错误或版权问题。
6. 每轮只修正一个主要偏差来源，例如画布、主面板、对象尺度、文字基线、颜色或阴影。

## 对齐策略

优先要求同尺寸精确比较。若候选尺寸不同，只允许在记录中显式启用：

- `stretch`：仅用于同构画布的渲染尺寸差异；
- `contain`：保持比例并补背景；
- `crop`：保持比例并居中裁切。

不要用自动变形掩盖 PPT 布局错误。字体渲染、抗锯齿和平台差异会造成不可消除的像素差，应记录而非无限迭代。

## 验收层级

- `STRUCTURE`：面板、对象、连接和阅读顺序正确；
- `VISUAL`：比例、颜色、字体、间距和层级接近；
- `PIXEL-QA`：在固定渲染环境下达到任务书设定的差分阈值。

对 AI 新生成或自有参考图，可以设置像素 QA 目标；初始建议为 `MAE <= 0.04`、`differing_pixel_ratio <= 0.15`，但必须根据图件复杂度、字体和渲染器调整。对外部论文结构重绘，不设置逐像素目标。

## 最终验收

- PPT 能正常打开，画布和对象数量合理；
- 所有关键文字可编辑且无换行、溢出或字体替换问题；
- 连接关系和科学内容正确；
- 数据、坐标轴和公式来自受控源；
- 参考图、PPT、渲染图、差分图和指标文件齐全；
- 记录最终提示词、来源权利、偏差和未达到的阈值；
- 人工视觉检查通过，不能只凭单一数值验收。
