# 实验到论文的可复现契约

## 目标

把代码与结果转化为审稿人能够核查的实验描述，同时阻止不同运行、数据和配置被错误拼接。

## 实验身份

每个可写入论文的正式结果至少记录：

- 代码版本或提交哈希；
- 数据集版本、清单或内容指纹；
- 训练/验证/测试划分及其生成方法；
- 配置文件和关键超参数；
- 随机种子与重复次数；
- checkpoint 身份；
- 硬件、软件和依赖版本；
- 运行 ID、时间和完整日志；
- 评估脚本版本与输出报告。

任一身份字段缺失时，降低证据强度并在论文边界中说明。

## 正式运行与 smoke

明确区分：

- `SMOKE`：验证代码链路、形状、依赖和输出，不支持最终性能结论；
- `PILOT`：探索可行性或估计参数范围，不作为独立测试；
- `ABLATION`：验证模块贡献，必须保持其余设置一致；
- `OFFICIAL`：按冻结协议完成、可进入论文主表的正式运行；
- `REPLICATION`：在相同或外部环境重复验证。

报告中不得用运行时长或 epoch 数之外的模糊命名掩盖身份。

## 公平比较

核对 baseline 与新方法是否共享：

- 数据与划分；
- 预处理与增强；
- 训练预算、调参预算和早停规则；
- 评价脚本与指标实现；
- checkpoint 选择规则；
- 推理条件与资源统计方法。

若不能共享，说明差异并避免直接因果归因。

## 深度学习最低检查

- 固定随机种子并报告非确定性来源；
- 明确 `train` / `eval` 模式；
- 验证 checkpoint 与模型结构匹配；
- 防止归一化、特征选择、先验或阈值使用测试信息；
- 不在单一测试集上反复选择模型；
- 报告重复实验的均值、标准差或置信区间；
- 分类任务报告类别分布、宏/微/加权指标及混淆模式；
- 不平衡任务避免只报告 accuracy。

## 结果身份链

推荐链条：

`release/code identity -> data identity -> config -> training trace -> checkpoint -> evaluation report -> table/figure -> manuscript claim`

对成对实验或消融，额外验证两个运行只在声明的变量上不同。

## 从代码写方法

不要逐文件描述实现。提取：

- 输入输出张量或数据结构；
- 模块职责与连接；
- 损失、优化和训练策略；
- 推理或部署路径；
- 与 baseline 的最小差异；
- 复杂度和关键设计依据。

所有形状、默认值和公式都从当前代码或冻结配置核验。

## 从结果写正文

1. 先确定哪些报告属于 `OFFICIAL`。
2. 从机器可读报告读取数值，不手工转抄多份。
3. 生成表或图后回读数据并比对。
4. 为每个结论附证据 ID。
5. 报告不支持假设的结果和失败运行。

## 最小验证优先级

1. 代码能否运行；
2. 输入输出形状是否正确；
3. 指标和损失是否在合理范围；
4. 是否破坏 baseline 或既有功能；
5. 是否支持正式重复实验和后续消融；
6. 是否完成论文要求的非 smoke 正式运行。

本地测试通过不等于服务器、集群或最终数据路径已验证。论文目标依赖外部运行时，必须验证实际打包、环境、启动脚本和结果回收链路。
