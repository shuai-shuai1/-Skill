# 证据、主张与结论边界

## 证据类型

| 类型 | 定义 | 可支持的典型表述 |
|---|---|---|
| `MEASURED` | 正式测量或正式实验产生的数据 | “实验结果表明……” |
| `LOGGED` | 日志、归档、系统运行记录 | “运行日志显示……” |
| `DERIVED` | 由已知数据按明确公式计算 | “根据记录计算得到……” |
| `THEORETICAL` | 公式、定理或模型推导 | “理论分析表明……” |
| `LITERATURE` | 可核验外部来源 | “已有研究报告……” |
| `SYNTHETIC` | 合成、演示、示意或 toy 数据 | “示意结果用于说明……” |
| `UNVERIFIED` | 未能核验来源或状态 | 不得用于确定性结论 |

证据类型不是强度等级。单次正式实验仍可能很弱；完整日志也不能替代独立测试。

## Evidence Ledger 最低字段

- `evidence_id`：稳定且唯一，例如 `E001`；
- `evidence_type`：使用上表枚举；
- `title`：证据对象；
- `source_path`：文件、URL、DOI、记录或数据集位置；
- `source_locator`：页码、表号、键名、行号或结果字段；
- `version_or_run`：代码版本、实验 ID、日期或数据版本；
- `claim_ids`：可支持的主张；
- `status`：`VERIFIED`、`PARTIAL`、`PENDING` 或 `REJECTED`；
- `public_release`：是否可以公开；
- `limitations`：证据不能说明什么。

## Claim-Evidence Matrix 最低字段

- `claim_id` 与 `claim_text`；
- `evidence_ids`；
- `section` 与 `figure_ids`；
- `allowed_wording`；
- `boundary`；
- `status`：`SUPPORTED`、`PARTIAL`、`UNSUPPORTED` 或 `CONTRADICTED`。

## 审计方法

对每条核心主张依次检查：

1. 证据是否存在且可定位。
2. 证据是否来自正确数据、代码和实验版本。
3. 对比对象、指标、单位和统计口径是否一致。
4. 证据是否直接支持主张，还是只提供间接线索。
5. 是否存在反例、失败样本或不支持假设的结果。
6. 主张是否超出了训练分布、测试集、运行时长或样本规模。
7. 图、表、正文和结论是否使用同一口径。

## 证据强度

- `A`：多来源一致、正式运行、身份完整、可复现，且有不确定性说明。
- `B`：正式证据充分，但外部验证或范围仍有限。
- `C`：单次、局部、间接或 smoke 证据，只能支持有限判断。
- `D`：synthetic、未验证、来源不清或与主张不匹配。

强度用于约束语言，不用于制造综合分数。

## 高风险混写

必须主动识别：

- 配置参数写成实测值；
- 理论上限写成系统达到的性能；
- 单次运行写成长期稳定；
- validation 最优结果写成独立 test 结果；
- smoke 或短 epoch 写成正式收敛结论；
- synthetic 曲线写成真实实验曲线；
- 训练集、验证集和测试集指标混用；
- 不同数据版本或随机种子的结果直接比较；
- 只展示有利结果而隐藏失败样本。

## 文献与引用真实性

引用外部来源时：

1. 优先查找原始论文、标准、数据集页面或官方文档。
2. 核验作者、题名、年份、期刊、卷期页码和 DOI/URL。
3. 不使用无法打开的二手摘要支持精确数字。
4. 不根据题名猜测研究结论。
5. 文中引用与文末条目双向匹配。
6. 撤稿、勘误和版本变化需要显式标记。

## 语言边界

- 只有统计检验和设计允许时才写“显著”。
- 只有比较设置公平且覆盖充分时才写“优于”。
- 只有明确的首创检索和证据时才写“首次”。
- 使用“在当前数据集和配置下”“该结果支持”“初步表明”约束有限证据。
- `SYNTHETIC` 只能用于解释方法、验证绘图流程或展示预期形态，不能支撑真实性能主张。

## 内部证据标签

写作阶段可在句末保留 `[E:E001]`。一条句子涉及多个证据时使用 `[E:E001,E002]`。这些标签用于审计，不是投稿引用格式；终稿可移除，但 Evidence Ledger 必须保留。
