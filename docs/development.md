# 开发规范

## 修改决策

先回答三个问题：

1. 这是触发/路由问题、方法论问题、稳定产物问题，还是确定性检查问题？
2. 是否能复用现有模块，而不是增加平行实现？
3. 修改是否会让系统把启发式判断误报为科学事实？

对应落点：

- 路由和不变量进入 `SKILL.md`；
- 详细方法进入 `references/`；
- 可复制契约进入 `assets/templates/`；
- 可确定验证进入 `scripts/`；
- 贡献者说明进入仓库根目录或 `docs/`。

## Python

- 支持 Python 3.10+；
- 使用类型注解、`pathlib`、`argparse` 和明确退出码；
- 所有文本使用 UTF-8 或 UTF-8-SIG 读入；
- 默认不覆盖输出，使用 `--force` 显式覆盖；
- 不使用裸 `except`，不静默 fallback；
- 错误写到异常或非零退出码，摘要写到标准输出；
- JSON 输出必须稳定、可机器读取。

## 自动检查规则

每条规则说明：输入、确定性或启发式性质、严重度、误报风险和修复建议。无法稳定识别的问题保留为人工检查，不要用复杂正则伪装成可靠检测。

## 测试

- 单元测试覆盖正常、错误和不覆盖现有文件三条路径；
- 使用匿名化或 synthetic 夹具；
- CLI 测试核对退出码和机器可读输出；
- 图像测试使用测试时生成的小型图片，不提交受版权保护的二进制图；
- 触发测试同时包含正例和反例。

## 发布

1. 检查 Git diff 和隐私数据；
2. 运行全部测试；
3. 运行上游 `quick_validate.py`；
4. 运行上游 `package_skill.py`；
5. 解包检查仅含 Skill 运行所需文件；
6. 创建明确提交；
7. 推送非破坏性分支或用户指定目标；
8. 发布时添加语义化版本标签。
